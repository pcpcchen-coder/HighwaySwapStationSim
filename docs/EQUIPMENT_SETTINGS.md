# 設備參數、個別效率與整套設定交換

入口：公開工作網站的「供電設計」與「效率對照」。適用工程版本 0.5.0；專案格式維持 1.3，設備設定檔格式為 1。

## 操作順序

1. 先選案例、設定連續天數與一期／二期，完成「站務配置」及「設備與容量」的配置。這些動作會重建拓撲，覆蓋個別額定、連線與效率。
2. 到「供電設計」，點設備或從「選擇設備」清單定位。可修改名稱、啟停狀態、額定功率、容量、功率因數、母線電壓／電流、槍電流／電壓等適用參數。
3. 在「效率對照」選「設備組裝乘積」。全域效率是未覆寫設備的預設；下方每台設備清單可開啟「使用個別效率」，輸入百分比。供電設計右側也可修改同一份設定。
4. 需要批次修改時，按供電設計中的「匯出設備參數 CSV」，使用 Excel 修改，再另存 **CSV UTF-8（逗號分隔）**，按「匯入設備 JSON / CSV」套用。整套設備、連線、站務與效率移轉請使用「匯出整套設備 JSON」。
5. 核對修改後的設備、效率來源、需求與停機排程。設備檔沿用目前逐時需求，不會把換電電量自動改成新的 SOC 窗口；必要時到逐時案例明確重算本日換電量。
6. 上方「JSON」備份完整專案 → 重新執行受限測算 → 確認快照同步 → 能量流核對輸入／輸出／損耗 → 匯出結果 XLSX。

只修改效率或個別設備参数不會自動重建拓撲；回頭改站務／工程配置、切期別或載入預設會重建。最後才作個別修改，並保存整套設備檔或完整專案。

## 哪些參數會參與運算

| 設備／參數 | 生效範圍 |
|---|---|
| 電網接入 kVA、PF | 限制電網輸出有功功率 |
| SST、PCS、DD／超充堆額定 kW | 限制該台輸出；不再乘自身轉換效率 |
| 箱變 kVA、PF、有效效率 | 輸入上限 `kVA × PF`；輸出上限 `kVA × PF × η` |
| 母線電壓、電流 | 限制 `V × A ÷ 1000`，並參與連接電壓檢查 |
| 槍 kW、最大電流、額定／車端電壓 | 限制額定功率及 `車端 V × A ÷ 1000`；車端超過額定電壓時不能供電 |
| 電池倉、終端、開關、線纜等功率額定 | 限制該節點通過或吸收的功率 |
| 交流站用節點額定 | 為供電上限；實際需求仍由站務、乘用車配置與負載係數決定 |
| 設備啟停、連線與停機排程 | 決定哪些供電路徑可用；排程到時會改寫當時啟停狀態 |
| A/B 站務電池容量、SOC、顆數、工位、服務時間等 | 影響該站庫存及服務；目前同站電池同規格 |

提高單台 DD／槍／堆的額定功率，不會自動提高站務中的每顆電池補電上限、單槍需求上限或共享功率池。兩層限制共同生效，還需考慮上游設備與其他負載。

以下是**規格紀錄**，在側欄單獨列出，CSV 可保留但不能改動成看似生效的新參數：電纜 `length` 尚無電阻／I²R 模型；補償櫃 `kvar` 不計無功補償；電池倉 `kWh` 的實際庫存以站務容量為準；乘用車 `slots/swapSeconds` 尚不產生乘用車交易。這些完整數值仍保存在設備 JSON 中。舊欄 `outputEfficiency` 僅為歷史紀錄，實際箱變效率使用下述規則，不併乘。

## 個別效率契約

支援 SST、箱變、PCS，以及 `charger` 類型的 DD／超充堆。未提供 `params.efficiency` 時繼承同類全域效率；有值時以該台設定優先。關閉「使用個別效率」會移除覆寫，恢復繼承。

畫面輸入百分比，資料儲存比例：98% → `0.98`。合法範圍為有限數字且 `0 < η ≤ 1`；不允許 0、負值、超過 100%、NaN 或 Infinity。明確設成目前全域值，與「未設定」不同：以後修改全域時，只有繼承者會跟著改。

`輸入功率 = 輸出功率 ÷ η`，`損耗 = 輸入 − 輸出`。每一段只算一次。DD／充電機效率包含內部 DD 與電纜，不再對槍、電池倉及被動元件追加相同損耗。被動元件目前理想效率為 1；不允許在其上新增轉換效率覆寫。

「來源全流程摘要」用路徑摘要校準舊模型，不能與單台效率混用。若已有單台設定，切回摘要模式會被驗證阻擋；先關閉覆寫或保持設備組裝模式。來源摘要本身也需能推導出不超過 100% 的分段效率。

效率對照頁上方的路徑比較是**全域預設摘要**；設備與容量頁仍為附件對稱案例估算，含既定倉數、額定與對稱假設。它們不代表個別設定後的真實拓撲結果。下方逐台有效效率及輸出容量反映單台設定；受限測算、能量流及元件帳反映同一次实际運算。

## 三種保存範圍

| 檔案 | 保存內容 | 匯入行為 |
|---|---|---|
| 整套設備 JSON | 全部節點及參數、連線及順序、全域／個別效率、A/B站務、工程配置、期別、停機排程 | 整套取代設備設定；不重新生成拓撲 |
| 設備參數 CSV | 所有既有節點的名稱、啟停、座標、數值參數及效率繼承狀態 | 依設備 ID＋欄位合併；保留未列出的值及既有順序 |
| 上方完整專案 JSON | 設備設定及需求、價格、天數、到站方式／種子、財務等 | 恢復完整情境，仍需重算 |

設備檔不覆蓋逐時需求、價格、目前天數、到站方式／種子、財務與情境名稱。整套設備 JSON 會取代期別與站務設定，若需求不同須再核對。停機排程超出目前天數時匯入失敗；先設定足夠天數再匯入。

「結果 XLSX」持續使用最後成功測算快照，含完整專案及單台效率。設備修改後立刻匯出 XLSX 仍是舊結果；請先重新測算。匯出設備 JSON／CSV 使用目前編輯資料；目前專案有不合法值／拓撲時會拒絕，未完成草稿可先用上方專案 JSON 保存。

## CSV 格式與範例

固定四欄：`equipmentId,type,field,value`。欄位順序可調整；設備 ID、類型必須與目前設計一致。範例把 A 區 SST 額定輸出改成 1,600 kW、效率 97%，B 區 SST 恢復繼承：

```csv
equipmentId,type,field,value
A-sst-0,sst,params.kw,1600
A-sst-0,sst,params.efficiency,0.97
B-sst-0,sst,params.efficiency,
```

| field | value 格式 |
|---|---|
| name | 非空白名稱，最多 120 字 |
| enabled | `true` 或 `false` |
| x、y | 有限座標數值 |
| params.kw、params.kva、params.pf 等 | 依設備規格範圍的非負有限數字 |
| params.efficiency | 比例 `(0,1]`；空白表示移除覆寫 |

CSV 是部分欄位合併，並非整列設備刪除／重建。不得同檔重複設定同一設備欄位。空白只對效率有繼承意義，其他數值不可空白。數字欄不能用公式、千分位文字或非有限值。輸出文字若可能被試算表視為公式，會使用可逆的前置單引號；匯入可還原原文字，請保留該保護字元。

JSON 以 `format: "HighwaySwapSim.EquipmentProfile"`、`version: 1` 標記，`settings` 含上表整套設備內容。`engineering` 必須存在，簡化模型明確填 `null`。拼錯／未知設定欄位不會靜默忽略；未知參數或不適用效率會拒絕。

檔案上限 8 MiB；CSV 最多 20,000 筆設定列。整批通過資料格式、參數、拓撲與排程預檢才一次套用；失敗時保留原設定。設備 JSON 可保存不同設備／連線陣列順序；CSV 合併不改原顺序，因為現行分配器依既定路徑順序配置功率。

## 可核對的驗證數值

100 kVA 箱變、PF 0.9、該台效率 80%，先供 12 kW 交流负載，剩餘供 PCS（75%）及 DD（50%），上游和各設備額定充足：

| 節點 | 輸入 kW | 輸出 kW | 損耗 kW |
|---|---:|---:|---:|
| 箱變 | 90 | 72 | 18 |
| 交流負載 | 12 | 12（末端吸收） | 0 |
| PCS | 60 | 45 | 15 |
| DD | 45 | 22.5 | 22.5 |

電網總輸入 90 kW；末端合計 34.5 kW；總損耗 55.5 kW。另以多日案例核對參數→購電→元件帳→能量流積分→XLSX往返；詳細結果與首次測試修正紀錄見 [驗證紀錄](VERIFICATION.md)。
