# 完整模型操作與原圖對照（v0.6.0）

本文件說明「完整物理案例」目前可計算的設備、設定生效方式、驗算及財務邊界。**元件已顯示、參數可編輯、模型已啟用、數值已驗證，是四件不同的事。** 圖面未提供的線材、效率曲線、儲能容量、乘用車電池、電價合約與設備成本，必須另填；不會因載入完整案例就自動變成已確認的現場規格。

## 1. 新舊案例與預設值

| 專案狀態 | 使用的計算方式 | 需要注意 |
|---|---|---|
| 含 `detailed.version=1`，且選「受限營運模擬」 | v0.6.0 完整引擎 | 執行前檢查已啟用模組的必要參數與設備連接 |
| 未含 `detailed` 的歷史專案 | 原 v0.5.0 引擎 | 保留原資料、拓撲及語義，不因開啟新版網站而自動改案 |
| 「來源原表重播」 | 原表算術重播 | 不會計算新物理元件或形成完整獲利結論 |

外層專案沿用 `schemaVersion=1.3`；`detailed.version=1` 是完整模型設定的版本。結果中的 `engineVersion` 才是該次實際計算引擎，不能只看網頁頁首版本。

「完整物理案例」會載入新的預設專案：513 kWh 重卡電池、20–100% SOC，預設每次補電 410.4 kWh；兩站各 8 倉，原圖每側 PCS 1,600 kW，倉 1–2 由 PCS 支路、倉 3–8 由 SST 支路供電。兩站換電 DD 外接槍合計 16 支，加上獨立超充 8 支，共 24 槍／12 個雙槍終端。此數量以預設站務配置為準，使用者修改後以當前節點清單及連接為準。

換電 DD 預設採回充／外充互斥，可改成同時共享。這是可編輯的設備矩陣假設，需由設備供應商確認；新增槍位不會增加 DD、母線或電網的供電能力。較晚補圖的 PCS 2,000 kW 是另一個方案值，請在同條件比較時明確調整，勿混用。

載入預設按鈕會重設整套專案。保留既有設計時先匯出完整專案 JSON；不要為了啟用新模型直接覆蓋唯一的舊案。

## 2. 建議操作順序

1. **保存基準與設定模擬期間。** 匯出目前完整專案 JSON，確認一期／二期、A／B 站、連續天數、容量及 SOC。新增日期或縮短天數後，重新檢查逐時資料、逐車事件與停復電排程是否仍在範圍內。
2. **在「完整模型設定」編輯草稿。** 依分區或參數路徑搜尋設備；修改標量欄位，使用「集合、曲線與事件結構」新增曲線點、儲能、到站事件、資產等。頁面百分比欄位沿用比例，98% 請填 `0.98`；金額是 CNY。
3. **套用草稿。** 只修改既有設備的曲線、負載、成本等，用「套用設定」。新增乘用車完整站、ESS／UPS、PV、ATS、共享端口或母聯連接等需要實體端口時，用「套用並重建設備連接」。重建會取代原供電設計的手動連線、位置及單台額定覆寫，應在細部設計之前完成。
4. **到「供電設計」檢查實際連接。** 核對各來源、開關、變流器、電池倉、終端與槍的路徑、啟停及容量；套回必要的自訂連線／單台參數。模型中的 `nodeId`、`sink`、`connectionNodeId` 必須對應存在的設備。僅填 ID 不會自動新增設備。
5. **編輯事件與價格。** 使用「逐時案例」設定每天每站的重卡需求與電價；有精確時間、車端 SOC 或雙槍一車需求時，在完整模型的服務分區設定逐車事件。再確認工程／站務參數未因後續操作重建拓撲。
6. **通過必要資料檢查後，按「執行測算」。** 套用不等於測算。必要資料或拓撲有錯時先修正；成功結果保存獨立的 `parameterSnapshot`。在測算期間或之後再編輯草稿，不會修改既有結果。
7. **到「能量流驗算」逐點核對。** 先看瞬時 kW，拉動時間軸確認到站、回充、母聯／ATS 切換、儲能充放電；再切累計 kWh，選全期或自訂區間，核對輸入、輸出、損耗、發電、外售及儲能增減。
8. **到「獲利能力」檢查成本完整性。** 核對來源電表、需量／容量費、存貨、成本、稅及長期營運假設。新增或修改財務設定後，同樣先套用並重新測算，避免新成本與舊設計結果混用。
9. **匯出可重播的紀錄。** 完整專案 JSON 保存目前設定；完整模型 JSON／CSV 保存該頁模型設定；結果 XLSX 保存最後成功結果及其設計快照。需要「最新設計的結果」時，必須先重新測算成功。

匯入完整模型 JSON／CSV 會套用 `detailed` 設定，保留專案其他部分，且不自動重建根拓撲。若匯入內容新增端口，仍須明確重建，再做供電設計檢查。只在表格中編輯而未按「套用設定」的草稿，不會被上方完整專案 JSON 包含；可先用本頁「匯出本頁草稿」保存。

### 2.1 用範本建立空集合的第一筆

在「集合、曲線與事件結構」選集合，再按 **「新增待填項目」**。支援的集合會產生可編輯欄位與不重複 ID；例如第一筆到站事件、逐包覆寫、ESS、PV、資產、營運費用、逐月假設與效率曲線。曲線範本只給可改的座標骨架，效率／溫度／電流等未知值保留 `null`，不以 100% 或零代填。

按鈕更新的是本頁草稿；填妥必要資料後還要按「套用設定」。新增實體端口時再明確重建，最後核對供電設計。時間 0、站別、曲線範圍與選項都是操作初值，必須改成自己的情境；自動 ID 也須核對實際設備。未支援快捷範本的集合仍可用 JSON 編輯器。

有啟用開關的物理模組可以先停用保存待填規格；負載、逐車事件、施工等沒有整筆啟用開關時，缺必要值仍會阻擋執行。施工列的 `enabled=false` 表示該時刻關閉指定設備，不能用它停用整筆排程。「複製最後一項新增」保留原項目資料，使用前要改 ID 和參數，不能當成空白模板。

新增或啟用會改變端口數的設定後，請重建連接。重建後再手動修改單台額定，實際引擎以測算快照中的拓撲與模型參數為準。效率曲線或箱變損耗模型**取代**該設備固定效率，不再相乘；同一設備不能同時啟用箱變專用損耗與轉換效率曲線。

完整乘用車營運啟用後，原本乘用車合計固定充電負載會由逐倉回充與站用模型接管，不能再把同一筆 500 kW 充電重複加成另一個負載。

一般站用的 `hourlyKW` 若有提供，該時段直接使用該時序值；沒有提供時才用 `idleKW＋perActiveJobKW×活動換電數`。`perEnabledSST=true` 時再乘啟用 SST 台數。這些是互相明定的計算分支，不是把時序、待機與作業負載全部相加。

## 4. 草稿、缺值與未啟用的意義

| 狀態 | 可以保存／匯出 | 對測算的效果 |
|---|---|---|
| 合法數值 `0` | 可以 | 表示使用者明確設定零；不代表未知 |
| 未知值 `null`／待填 | 合法草稿可以 | 必要的已啟用欄位缺值時停止對應計算，不偷偷補零 |
| 物理模組 `enabled=false` | 可以保留其完整設定 | 不套用該附加模型；例如未啟用線纜阻抗時維持理想容量支路 |
| 已啟用且參數齊全 | 可以 | 仍須設備存在、範圍合法、曲線覆蓋及連接有效，才能執行 |
| 未知欄位／不支援版本／非法數值 | 不接受套用或匯入 | 整批拒絕，避免「匯入成功但欄位被丟棄」 |

部分可選限制另有明定含義：例如 `currentLimitA=null`、`rampKWPerMinute=null` 表示沒有額外限制；DC 線纜不要求 AC 電抗／PF。不要一律把所有 `null` 改成 0 來消除缺項。

「物理測算必要資料」清單檢查的是本頁草稿。財務缺值在獲利能力分開顯示：物理資料齊全時可以算能量，即使成本未齊；成本未齊不能據此顯示完整淨利或投資回報。

## 5. 車輛事件與電量邊界

`detailed.service.useHourlyTruckDemand=true` 時，逐時重卡列會產生到站事件；明確填寫的 `swapArrivals`、`chargeArrivals` 會另外加入，**不是覆蓋同時段逐時需求**。兩者重複輸入會重複計車。完全採逐車事件時關閉逐時轉事件，但仍保留完整逐時電價資料供源電表計價。

逐時資料每列按車次平均分配電量；到站方式沿用等距或固定種子。換電回站 SOC 由該筆補電量推導，必須在允許窗口內。直接充電的固定電量模式按充電端口交付量收費；SOC profile 模式則先按有效容量與 SOC 差得到車內儲能，再透過內效率換算端口交付量。單車兩槍仍是一筆車輛交易，不是兩筆收入。

逐車 `atMinute` 是從整個模擬起點算的絕對分鐘；次日 09:00 是 `1980`。可供使用者輸入的 profile 以 SOC 半開區間採分段常數，不會偷偷插值；需提供覆蓋目標 SOC 的電壓、電流、功率及溫度區間。

周轉電池可逐包指定初始 SOH，但目前不能把這個輸入宣稱為經驗證的周轉電池自動壽命預測。ESS／UPS 的日曆／循環衰退是另行啟用的簡化係數模型；財務更換則由使用者排程，不自動代表物理電池在同月已汰換。

## 6. 瞬時與累計驗算

瞬時模式顯示該時刻的 kW；累計模式把連續功率對指定的 `[起點,終點)` 積分為 kWh，離散庫存事件則按第 6.1 節端點政策列帳。區间可加性是必要檢查：`E[0,24h) = E[0,12h) + E[12h,24h)`，不能把終點又算一次。零功率只代表該時段沒有能量流，不等於設備未帶電。

檢查一台轉換設備時核對「輸入＝輸出＋損耗」；檢查母線時核對入線與出線分配；檢查儲能時還要包含庫存增減。全站邊界為：

`電網購電＋實際採集光伏 = 對外服務交付＋站用＋模型損耗＋外售電量＋周轉電池能源增加＋ESS/UPS能源增加`

庫存減少是負的「能源增加」。光伏棄光未進入站內能源，不計成已發生熱損；ESS 放電是期初／前期儲能的移轉，不是又一次購電或憑空新增發電。換電出售的電量是電池出入庫的淨交付，不可把早先回充到倉位的電量再加一次當售電。

全站驗算應使用 `detailedResult.energy` 與電池／儲能帳。不要直接把所有節點輸出加總當全站輸出：同一度電經過 SST、母線、DD、電池倉會出現在多個節點。結果、圖面及結果 XLSX 使用同一次成功快照；新設定生效後重算才能逐項核對。

### 6.1 任意時間窗、自放電與容量溢出

累計可以選不是整分鐘或整小時的起訖。線路功率與連續回充／放電用 `[from,to)` 積分；儲能自放電用已保存的初始庫存、充放功率、效率及自放電係數計算連續時間解，子分鐘窗口不是按整段平均損耗分攤。每台 ESS／UPS 都列起末庫存、充放電、轉換損耗、自放電與守恆殘差。

容量衰減使可容納能源下降時，超出的能源列為離散 **spill kWh**。儲能端點採調整後庫存，這類步末調整按 `from < t ≤ to` 歸入前一區間；因此 `[a,b]` 與 `[b,c]` 的庫存差及離散損失可以相加，沒有重複事件。連續電流／功率依舊採 `[a,b)`，兩種時間口徑會在畫面與匯出中分別標示。空區間累計為零。

當下模式顯示瞬時自放電 kW 及庫存變化率 `dE/dt`；此刻離散容量損失仍是 kWh，不除以步長當成連續 kW。換電完成事件則用 `from ≤ t < to`，恰在模擬期末完成者歸入最後關帳區間。查看事件時請以畫面揭露的端點政策為準。

圖面全站外部帳核對「電網＋實際光伏−外售−服務及站用末端−網路損耗−儲能被動損耗−儲能變化」。其中服務末端包含換電電池回充；營運帳改用「換電淨交付＋周轉電池庫存變化」，兩種帳不能再相加。儲能轉換損耗已在圖面設備內，只另補自放電與容量溢出。

缺少已保存的儲能／服務時間範圍，或帳本不完整時，對應驗算顯示未計算並要求重算，不能猜零或拿目前草稿補舊快照。全圖數值 JSON 會保存選定區間及同一次結果的 `parameterSnapshot`。


## 7. 財務設定與可出結論範圍

| 項目 | 參數路徑 | 計算口徑與限制 |
|---|---|---|
| 起始日期／時區／部分月 | `detailed.finance.calendar` | 起點是當地午夜，固定 UTC offset；不處理夏令時間 |
| 容量／15 分鐘需量／超約／PF | `detailed.finance.meters[]` | 依實際 source 電表；15 分鐘固定鐘面區間積分，不拿瞬時峰代替需量 |
| 能源存貨估值 | `detailed.finance.inventory.pools[]` | 填期初價值與其他轉換成本；採周期加權，不是逐筆移動平均；ESS→換電池內部轉撥在合併時消除 |
| 逐設備投資／租賃／處置 | `detailed.finance.assets[]` | 自有、租賃、第三方分開；購入月、處置月、折舊、殘值皆須明填；新增資產成本與停機事件不自動連動 |
| 人力／維保／租金等 | `detailed.finance.opex[]` | 可按曆月、營運日、交付 kWh、收入比例設定，另含起止月及調漲假設 |
| 稅／應收款／準備金 | `detailed.finance.tax/workingCapital` | 有明示簡化稅模型、固定收款延遲、期初投入及準備金；不代表完整當地稅務或租賃準則 |
| 長期 NPV／現金流 | `detailed.finance.investment` | 每月營運假設需齊全，且 `projectionInputsConfirmed=true`；不把數日運轉直接冒充完整月份或年度結果 |

`REQUIRE_FULL_MONTH` 不會用數日觀測值生成完整月帳單。`PRORATE_OBSERVED` 依實際曆月天數分攤觀測到的基本／超約費，屬觀測估計；全月真正最大需量仍未知。PF 帳單需要使用者提供的月 PF 或明示調整，不把設備額定 PF 當成已量測月 PF。

購電費已包含供應模型損耗所需的電量，不再扣一次「損耗成本」。存貨成本調節把購電現金支出與當期能源費用分開。折舊影響損益及稅，購入／替換才是 CAPEX 現金支出。租賃此處採租金模型，不是完整 IFRS 16 會計；收入比例稅不是 VAT 進項抵扣模型。

即使資料完整，結果仍是指定假設下的營運／投資測算。`null` 必須保留為「尚不能計算」，不能以零填補後宣稱獲利。新增母線、端口等實體節點會帶出成本清單，但並非每個虛擬共享端口都要再買一件設備；請據真實 BOM 校正數量、所有權及與上層設備的成本歸屬，避免重複計價。

## 9. 必須與驗證結果一起揭露的邊界

1. **準靜態能量模型。** 有向供電路徑與共享容量計算沒有求解全網 AC 相角、諧波、暫態、並聯環流或電磁短路過程。
2. **分支電壓是明定邊界。** 線纜模型使用設定的送端電壓求單支路電流、I²R 及受端壓降；受端電壓不是自動傳遍全網的潮流解。多條串接線纜或可調 DC 母線要檢查各支路電壓假設是否一致。
3. **保護是設定式事件。** 外加故障電流、整定及延時決定開斷／復歸；不由網路阻抗自動算真實故障波形，不可用於現場保護協調或分斷安全認證。輸入故障電流超出分斷額定時不能假定成功切斷。
4. **熱與爬升是離散近似。** 熱模型為分段固定損耗／環境下的一階 RC；控制步長上限一分鐘，另在到站、完工、SOC／保護／切換等邊界切步。爬升上限依前一步輸出與經過分鐘更新，採區間常功率積分，不是連續線性 ramp 的波形面積。
5. **EMS 是可重播的啟發式規則。** 來源價格排序、優先及輪轉只決定可行分配；沒有全期最優證明。預看使用已提供的未來到站事件，不代表已建立現場需求預測模型。
6. **電池／車輛仍有範圍限制。** 車端 profile 是使用者提供的 SOC／溫度分段；每包 SOH 輸入不是電化學老化模型。ESS／UPS 簡化衰退與財務替換月份仍需現場校準及人工一致性檢查。
7. **財務依明示合約與假設。** 不預置任一地區完整供電規則、稅務或會計準則；部分月估計、租賃、應收與生命周期假設都有適用範圍。

三個新增多日案例 V04（共享 DD／母聯，3 日）、V05（PV／ESS／UPS／ATS，4 日）、V06（乘用車／來源計費／跨月帳單，5 日）用獨立預期值比較實際完整引擎。V01–V03 維持歷史模型回歸用途。案例數值、適用版本、誤差及缺陷修正應以本次提交的驗證紀錄為準，不能把研究原型、較早的測試通過數或本說明書視為新版本已全數驗收的證據。

對外可以使用的敘述是：「在本次指定模型、參數、版本、情境及容差內，獨立重算、事件與能量帳驗證通過；未建模現象與現場資料誤差另列。」**不能宣稱本系統對所有場站與所有未來情境百分之百正確，或保證實際獲利。** 現場導入仍需同步電表、SOC、交易、故障／氣象時序與成本合約，以獨立保留期間驗證用途容差。
