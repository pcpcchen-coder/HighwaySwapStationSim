# 電池回充修正與逐艙 SOC 驗算（0.7.0）

## 修正原因

0.6.0 將逐時換電 kWh 除以站級標稱容量，先生成回站 SOC；實際換電卻使用個別電池容量及 SOH，兩者不一致時會改變原始需求。重現條件為 513 kWh、SOH 80%、20–100% 窗口、輸入單次 410.4 kWh；舊結果實際交付 328.32 kWh，少了 20%。這是需求語意錯誤，即使能量守恆通過，也不能視為正確。

0.7.0 保留逐時表每車 `swapKWh / swapCount` 的絕對需求，配對實際出站、回站電池後才決定回站電量。無法在 SOC 下限與目標上限內滿足時，不完成該交易，需求及未交付 kWh 保留，收入不產生。不同容量的可服務車輛可繼續配對；未完成仍須檢查庫存、工位、供電與窗口，不將所有排隊都歸因於 SOH。

精確逐車事件支援兩種互斥輸入：

| 需求方式 | 設定 | 意義 |
|---|---|---|
| 回站 SOC | `returnSOC`；`requestedKWh`、`minReturnSOC` 為 null 或省略 | 淨交付由實際出／入站電池能量決定 |
| 絕對淨交付電量 | `requestedKWh`、`minReturnSOC`；`returnSOC=null` | 原始需求不可因 SOH、容量或曲線而縮放 |

## SOC、充電功率與能量

有效滿能量為 `C × SOH`。未提供能量曲線時，`E(SOC)=C × SOH × SOC`；提供 `battery.energySOC` 後，使用使用者的 SOC／儲能比例分段線性對照 `E=C × SOH × f(SOC)`。曲線須嚴格遞增，端點為 `(0,0)`、`(1,1)`。中间點可以先保存 null 草稿，必要資料未填齊時禁止使用該曲線測算。

每艙 `chargeBands` 可設定完整 0–1 SOC 範圍內，各段的電壓、最大電流與最大功率。請求功率為單艙功率、分段功率、`V × A / 1000` 三者最小值，再受上游實際供電與調度限制。零功率分段可以表示 BMS 不接受充電，SOC 不會自行前進。

實際區段長度不是固定 7.5 分鐘。引擎以最長 1 分鐘為外層切步，遇到到站、換電完成、SOC 功率邊界、目標達成、停機等事件再細分。每段計算：

`端口輸入 kWh = 實際分配 kW × 分鐘 / 60`

`增加庫存 kWh = 端口輸入 kWh × chargeEfficiency`

`電池內損耗 = 端口輸入 − 增加庫存`

更新庫存後反解同一能量曲線得到 SOC。DD、SST、PCS、線路損耗另在上游計算，不重複乘在電池端。電池庫存節點不得以通用轉換／電纜模型取代單艙充入效率；相應損耗應設在上游獨立節點。

沒有 BMS 或實測曲線時，不假造 CATL 充電特性。null 曲線沿用固定功率／線性能量假設；100% 電池充入效率也會提示確認。驗證案例的分段曲線是合成測試資料。

## 操作順序

1. 在「完整模型設定」按「準備逐艙 SOC／回充參數」，將目前繼承的單艙數值展開至本頁草稿。既有個別覆寫不被取代。
2. 在「乘用車／逐電池／逐車」分區按艙位搜尋，編輯容量、SOH、初始 SOC、充電功率及內部效率。曲線集合可以新增待填項目、修改分段及對照點；完成結構編輯後先檢核。
3. 新建的個別覆寫會固定目前單艙設定。以後修改站級共用參數時，也要修改個別覆寫；或停用覆寫以恢复繼承。
4. 套用設定並重新執行受限營運模擬。僅修改 SOC、曲線與回充參數不需重建連接；改端口或增設備才依需要重建。
5. 開啟「能量流驗算」，拖動時間軸，或輸入任意精確分鐘。每個電池艙顯示 SOC 及狀態，點艙位查看電池編號、庫存／待補電量、端口輸入與實際入庫功率。
6. 累計模式中，kWh 是所選期間積分；SOC、庫存及艙位狀態是游標終點的狀態，不累加 SOC。在換電完成的同一時刻，顯示剛換回的低 SOC 電池；之前仍顯示待換出的電池。
7. 保存完整專案 JSON，或匯出完整模型 JSON／CSV 保存所有曲線與 null。結果 XLSX 使用最後成功快照，新增 `Battery_SOC_Trace` 工作表，包含每個恆功率區段的起訖時間、起訖 SOC、電量、功率與電池身份；能量曲線另存於 `Battery_SOC_Curves`，以曲線 ID 對照，避免塞入單一超長儲存格。全圖 JSON 另含目前游標所有艙位狀態。

期末 SOC 是完成期末事件後的庫存狀態。期末電池時序的零長度結帳列不計新增能量，也不推測模擬期後供電；線路功率仍依原規約顯示期末左極限。舊結果沒有電池時序時顯示「—」，須重新測算，不能把缺資料解讀為 0%。

在「獨立案例驗證 → 電池 SOC 三日驗證」可以載入三個固定案例並執行；頁面會比較本次結果，可展開逐時明細並匯出比對 JSON。輸入被修改或時序缺失時不沿用通過結論。

## 驗證口徑

以獨立 Decimal 計算建立三個 3 日案例：線性 SOC＋分段回充、非線性能量對照＋分段回充、非線性對照＋降額與停電。比較完整引擎的交付、購電、電池損耗、分段完成時刻與時間軸讀數，另核對逐節點／線路帳本。

SOH 衝突、可行固定需求、顯式 SOC 事件、個別回站電池、曲線缺值、零功率、邊界、快照匯出還原均另設回歸。實際執行結果與檔案見 [驗證紀錄](VERIFICATION.md)。

通過上述驗證能證明列示輸入在明定模型下符合獨立期望，不能保證所有現場條件或獲利一定正確。對外報告應同時提供輸入快照、引擎版本、測試範圍、容差與實測校準狀態；不只提供一個「守恆通過」結果。
