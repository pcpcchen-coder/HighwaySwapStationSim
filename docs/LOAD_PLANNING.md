# 高、中、低逐時劇本與十年估算

更新：2026-09-18。來源為本次提供的四张截圖；原始圖片不進 Git，轉錄與 SHA256 位於 `data/reference/load-scenarios-2026-09-18.json`。舊八月 fixture 保留，未用新數字覆蓋歷史重播。

## 操作與連動

1. 在「逐時案例」載入高／中／低負載。兩站全部模擬天數套用該代表日的車次、電量與價格；設備、SOC、停機、逐車事件保留。完整預設每側 PCS 3 倉、SST 5 倉，共用充電 PCS 1 樁、SST 2 樁（每側3樁6槍）。
2. 「AC・DC 分流」編輯總量與 AC 子集，DC 自動相減。AC 是 PCS 母線、DC 是 SST 母線，不是車端交流慢充／直流快充分類。次數與電量分別相減；分支內按車次平均分配電量，兩分支仍競爭同一換電工位。
3. 可獨立編輯每天。要讓十年設計採用修改後的代表日，選定高／中／低，按「將第 N 天 A＋B 更新至…劇本」。此操作明確保存兩站一天，不會把多日差異默默覆蓋。載入劇本會同步設定儲存目標。
4. 「十年估算」可調整每年負載、營運日、折算係數、兩方案的加權效率與節電價值。預設2027低、2028–2029中、2030–2036高。圖表展示 AC/DC 年度需求、年度與累計節電收益。
5. 按「驗證高・中・低設備能力」，用當前設備逐一執行三個24小時代表日。需求、交付、未交付、庫存及全站購電來自實際引擎。設備／劇本變更會使舊結果失效；年度折算或節電價值修改不必重新跑同一代表日。
6. 「查看能量流」把所選結果快照交給既有能量流、結果與獲利能力頁；不覆蓋正在編輯的逐時草稿。結果 XLSX 匯出同一快照，專案 JSON 保存目前草稿。完整財務缺少合約、資產、稅务資料時繼續顯示待填。

## 年度公式、單位與邊界

年度截圖沒有單位，頁面明確按萬kWh、萬元CNY解讀。預設節電價值0.67 CNY/kWh由來源節電量／增加收益比值推定，可修改。相同中負載在2028、2029有不同年售電量，故不能只用日需求×365冒充來源公式。

- 預設年度折算係數＝來源SST年售電量 ÷（該劇本每日DC電量 × 365）。这是推定的規劃折算值，不是設備容量利用率。
- 年售電需求＝當前保存的代表日電量 × 營運天數 × 折算係數。
- 比較相同客戶端DC電量 Q：傳統購電＝Q/η傳統，SST購電＝Q/ηSST；節電＝兩者之差。
- 節電收益＝節電量×每度電價值，允許負收益；不宣稱是扣完設備價差、OPEX、稅務或折現的淨利。
- 來源加權效率作为年度輸入保留，不再次乘上各設備效率。當前設備效率另透過代表日實際引擎影響交付、購電與電量費。
- 可交付、未交付、全站購電與電量費以代表日實際值乘等效日數。全站數字包括其他設定負載；電量費不含基本費／需量費／固定費。當車輛電池庫存或ESS/UPS總庫存未補回、或折算係數>100%時，不給容量外推值。

這是代表日規劃，並非連續十年逐事件模擬；不自動推定老化、擴建、電池壽命或季節曲線。第一天的设备排程、競爭負載、人工逐車事件沿用当前输入。使用者仍需在完整模型驗證連續多日、季節與施工工況。

原圖顯示效率與效率差／節電量有差異：中負載95.96%−92.56%=3.40百分點，原圖3.39%；高負載95.85%−92.88%=2.97百分點，原圖2.96%。不補造不可見公式。來源對照表並列原圖售電、節電、收益與重新計算值。現有默认十年DC售電16,182.14萬度，重算節電562.5850243306萬度、節電收益376.9319663015萬元CNY。

## 資料與匯出

`ServiceRow.ac` 是可選子集；沒有該欄位的歷史專案保持原行為。有分流的受限模式必須使用完整物理模型，避免舊引擎忽略分流。`SwapArrival.allowedSlotIds` 限制換電配對；充電使用既有allowedGunIds。分支由实际拓撲的PCS/SST共享群組追溯，不按固定倉號猜測。

需求JSON v2保存AC物件，v1相容；CSV追加acSwapCount、acSwapKWh、acChargeCount、acChargeKWh四欄。四欄全空表示未分流，部分空白拒絕。非法子集、負DC、零次數卻有電量均拒絕。

完整專案JSON保存三代表日和十年設定。結果XLSX追加Ten_Year_Settings、Ten_Year_Design、Ten_Year_Estimate、Load_Presets、Service_AC_DC；容量三次比較屬當次頁面快取，不在單次結果XLSX中冒充已驗證，可另外匯出十年CSV與估算JSON。頁面重整後容量結果需重跑。

## 驗證

`npm run verify:load-planning` 用不讀應用程式／來源JSON的Python Decimal基準，核對110項年度值；三個完整引擎代表日、守恆與容量結果存於 `docs/evidence/2026-09-18/load-planning-verification.json`。核心回歸另驗證來源小計、分流實際配對、樁槍數、SOC同步、快照失效、匯入匯出與財務缺值。
