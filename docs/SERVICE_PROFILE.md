# 逐時需求編輯、匯入與匯出

適用版本：0.4.2。入口：「逐時案例」。需求檔保存目前編輯中的資料，無須先執行測算。

## 建議操作順序

1. 先選起始案例，設定「連續天數」及站務配置。新增日會複製第一天需求；縮短期間會移除超出天數的列，應在需求細修前完成。
2. 到「逐時案例」選服務區、日期，直接修改 0–23 時的換電車次、換電總 kWh、充電車次、充電總 kWh、購電價及服務費。
3. 批次編輯時按「匯出需求 CSV」，以 Excel 開啟並修改，再另存為 **CSV UTF-8（逗號分隔）**。保留完整欄名，儲存實際數值，不輸出公式或千分位文字。也可使用「匯出需求 JSON」。
4. 回到「逐時案例」，選「合併列入資料」或「取代全部天數」，按「匯入需求 CSV / JSON」。讀取成功後顯示套用列數；任何列不合法時整批拒絕，不會套用部分資料。
5. 核對本日到站車次、總需求、到站方式、計價方式與「本日需求待核對」提示。需要將換電需求改成目前電池物理窗口時，明確按「本日換電量依 SOC 重算」。此動作只修改所選日、所選站的換電總 kWh。
6. 上方「JSON」備份完整設計與需求。設定受限營運模擬並重新執行，確認「快照已同步」後，檢查能量流、未交付需求及財務結果，再匯出「結果 XLSX」。

直接編輯與需求匯入不重建供電拓撲。檔案只更新逐時 `services`：站務、供電設計、效率、成本、到站方式、隨機種子與計價方式皆沿用目前專案。欲保存或重現完整情境，另存上方專案 JSON。

## 需求如何變成車輛事件

- 車次代表該小時到站數，總 kWh 是所有到站車輛的合計需求，不是每台車電量，也不是 kW 額定功率或已完成交付量。
- 同站、同小時、同類服務的每台車分配 `總 kWh ÷ 車次`。例如充電車次 4、充電總量 100 kWh，會生成 4 台各需 25 kWh 的車。
- 「均勻排定」每小時從第 0 分鐘開始等間隔到站；4 台為第 0、15、30、45 分鐘。「固定種子隨機」在該小時內抽樣，保持完整專案、列順序和種子相同才可重現相同事件。換電與充電分別產生事件。
- 第 2 天 12 時的上述 4 台車，絕對到站分鐘為 2160、2175、2190、2205。排隊及未完成服務跨午夜延續。
- 受限模擬會按設備、功率及庫存決定實際交付量；需求增加不保證能完成。來源原表重播僅重播算術，不能代表設備承載能力。
- 換電單次需求須與 `電池容量 ×（readySOC − returnSOC）` 相符。513 kWh、20%→100% 為 410.4 kWh。來源 410 kWh 原值會保留並提示；未吻合者在受限模擬中保留排隊，不能用修改來源資料掩蓋差異。
- 目前提供逐時事件生成，尚無每台車個別指定到站秒數、車型或不同電量的事件清單編輯器。

## CSV 欄位

檔案匯出全部天數及兩站，固定 13 欄；匯入允許調整欄位順序。`day + station + hour` 是唯一鍵。請勿使用結果 XLSX 中的 `Service_Profile` 表直接替代此格式；其內部 day 從 0 開始。

| 欄位 | 意義／單位 | 合法值 |
|---|---|---|
| day | 第幾天 | 整數 1–目前連續天數 |
| station | 服務區 | A 或 B |
| hour | 小時 | 整數 0–23 |
| swapCount | 換電到站車次 | 整數 0–1,000 |
| swapKWh | 換電總需求 kWh | 非負有限數字；零車次時須為 0 |
| chargeCount | 充電到站車次 | 整數 0–1,000 |
| chargeKWh | 充電總需求 kWh | 非負有限數字；零車次時須為 0 |
| gridPrice | 購電價 CNY/kWh | 非負有限數字 |
| swapFee | 換電服務費 CNY/kWh | 非負有限數字 |
| chargeFee | 充電服務費 CNY/kWh | 非負有限數字 |
| swapTotalRaw | 來源換電總價 CNY/kWh | 非負有限數字 |
| chargeTotalRaw | 來源充電總價 CNY/kWh | 非負有限數字 |
| idleRaw | 原始「閒」欄，僅供追溯 | 非負有限數字；空白或 null 表示未提供 |

合併範例：第 2 天 A 區 12 時改成 4 次充電，共 100 kWh，無換電。

```csv
day,station,hour,swapCount,swapKWh,chargeCount,chargeKWh,gridPrice,swapFee,chargeFee,swapTotalRaw,chargeTotalRaw,idleRaw
2,A,12,0,0,4,100,0.5,0.3,0.3,0.8,1.17,
```

精確電價模式下，這筆充電單價為 0.5 + 0.3 = 0.8 CNY/kWh；來源總價模式下使用 1.17。完整交付 100 kWh 的收入分別為 80 或 117 CNY。購電價仍供購電成本計算。修改服務費／購電價不會自動覆寫兩個來源總價；來源總價模式時表格會展開對應欄位。

## 合併、取代及錯誤規則

| 方式 | 套用範圍 | 完整性要求 |
|---|---|---|
| 合併列入資料（預設） | 更新檔案列出的鍵，未列出的時段保留 | 至少 1 列；每列仍須有 13 欄 |
| 取代全部天數 | 更新全期兩站逐時需求 | 每天兩站各 24 列，共 `天數 × 48` 列 |

合併以完整列取代，不是只改單一欄位；同列其他數值請一併保留。檔案列順序不改變專案既有列順序，避免固定種子隨機到站改變。任何方式都不修改目前連續天數；資料超出範圍時，先調整天數再匯入。

檔案上限 2 MiB、最多 1,488 資料列，期間最多 31 天；合併完成後全期換電與充電車次合計最多 20,000。缺欄、重複欄、未知欄、重複鍵、越界日期／小時、負值、小數車次、空白必要數值、非有限數字、公式文字或資料不完整會拒絕。正車次搭配零需求會保留，畫面提示核對；換電還須通過 SOC 契約。

## 需求 JSON

檔案類型標記為 `HighwaySwapSim.ServiceProfile`，`version=1`、`dayBase=1`，`horizonDays` 為匯出時宣告天數，`rows` 為上表 13 欄物件陣列。數字使用 JSON number，`idleRaw` 未知值使用 JSON null。

宣告天數是來源資料上界，匯入不因此調整目前期間。只含部分時段的 JSON 可以合併，只要資料日數同時在檔案宣告及目前專案範圍內。

上方專案 JSON 包含完整設定；需求 JSON 只包含需求與價格；能量流 JSON 是驗算記錄。三者用途不同。結果 XLSX 仍是上一次成功測算快照；直接用 Excel 修改其顯示表不會經此需求匯入流程套用。批次修改需求請使用這裡的 CSV 或 JSON。

## 驗證範圍

自動測試涵蓋多日精確往返、部分合併、全期取代、錯誤整批拒絕、固定種子事件順序、獨立到站／電量／價格／購電期望值、SOC 明確重算，以及介面控制項的伺服器渲染。完整結果見 [驗證紀錄](VERIFICATION.md)。
