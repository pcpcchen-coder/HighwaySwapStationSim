# 換電 SOC 設定與驗證

更新：2026-09-09；工程版本0.5.0／schema1.3。

## 設定入口與規則

「設備與容量」及「站務配置」皆可設定A、B站各自的回收SOC下限、交付SOC上限。畫面使用百分比；專案資料沿用`station.A/B.returnSOC`、`readySOC`的0–1比例。

有效範圍為`0 ≤ 下限 < 上限 ≤ 100%`，電池容量大於0且不超過5000kWh。支援0–100%及小數百分比；空白、非有限值、相等、反向與越界不能套用。

先查看預覽，再按該站「套用SOC並同步全期換電需求」。未套用輸入不進入測算或匯出，切頁、匯入或修改同站其他參數前應先套用。兩站重算按鈕使用目前**已套用**的上下限，不會讀取未套用輸入，也不改名稱、模式或來源註記。

## 電量與資料連動

每次換電補能量＝電池額定容量×（交付SOC上限−回收SOC下限）。例如513kWh、20–80%為307.8kWh；20–100%才是410.4kWh。

`packages/station-settings`在回傳新專案前驗證資料。套用單站時更新該站SOC及所有日期的`swapKWh`，每列為`swapCount × 每次電量`。保留服務列順序、車次、直接充電需求、價格、另一站、設備接線／位置、單台效率、停機排程、情境名稱、測算模式及財務設定，不重建拓撲。

引擎物理公式未改：期初電池庫存採交付SOC，換電完成後回收至下限，再依真實供電能力補到上限。這是同站換電電池的共用設定，尚不是逐車SOC、單槍充電SOC曲線或乘用車完整模型。

靜態容量摘要使用A區目前SOC及附件對稱配置；A/B不對稱設計應以實際受限模擬、來源電表及能量流為準。操作順序：套用 → 保存完整JSON → 受限測算 → 驗算 → 匯出結果XLSX。

## 匯入／匯出

| 檔案 | SOC與需求保存方式 |
|---|---|
| 頂端專案JSON | 目前已套用的兩站SOC、全期需求及完整設計 |
| 結果XLSX | 上次成功測算的SOC、需求與結果快照；修改後須重算 |
| 整套設備JSON | 保存兩站SOC；匯入不修改目前需求，需再按套用同步 |
| 需求CSV／JSON | 保存重算後的需求kWh及價格；不包含站務SOC |
| 設備參數CSV | 僅設備節點參數；站務SOC使用整套設備JSON或專案JSON |

既有來源fixtures保持不變；使用者明確套用時才改目前專案的需求。既有「本日換電量依SOC重算」仍只重算所選站日。

## 新增三日解析驗收

取V01的簡化SST測試配置建立新專案，不覆寫原fixture：兩站各一顆513kWh電池、每天0分各到站一次、換電7.5分鐘、電池端補電50kW、零輔助負載，SST98%、DD95%；購電單價0.5、售電單價0.8CNY/kWh。A採20–80%、B採30–80%。

| 項目 | 獨立預期 | 系統結果 |
|---|---:|---:|
| A每次交付kWh | 307.8 | 307.8 |
| B每次交付kWh | 256.5 | 256.5 |
| 三日總交付kWh | 1692.9 | 1692.9 |
| 完成次數／未交付kWh | 6／0 | 6／0 |
| 期初／期末庫存kWh | 820.8／820.8 | 820.8／820.8 |
| 購電kWh | 1818.3673469387755 | 1818.3673469387755（容差內） |
| 損耗kWh | 125.4673469387755 | 125.4673469387755（容差內） |
| 收入CNY | 1354.32 | 1354.32 |
| 購電支出CNY | 909.15 | 909.15 |

獨立能量式：`3 × (307.8 + 256.5) = 1692.9`，購電為`1692.9/(0.98×0.95)`。每站初期庫存為`513×0.8=410.4`；每天補滿分別在第376.86與315.3分鐘，下一日可再次服務。

依現行逐來源、逐小時結算政策，A每日費用`23.50 + 5×26.85 + 7.55 = 165.30`，B每日`23.50 + 4×26.85 + 6.85 = 137.75`，三日909.15元。不能以總購電一次乘電價取分（909.18元）代替逐時結算。收入減購電445.17元，並非會計淨利。

測試另驗證：全期與他站隔離、非法輸入原子拒絕、0–100%與小數百分比、保留自訂拓撲、能量流全期積分、專案JSON／設備JSON／需求CSV／XLSX還原與重新執行一致。結果詳見[測試程式](../tests/station-settings.test.ts)與[驗證紀錄](VERIFICATION.md)。

以上為固定參數案例與明定模型的驗證，未執行瀏覽器操作或場站實測；不代表任意輸入或真實獲利百分之百保證。
