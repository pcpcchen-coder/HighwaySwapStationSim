# 能量流驗算介面 — 0.4.0

新增「能量流驗算」頁籤。沿用使用者授權的同一公開網站、同一 GitHub 專案。此頁閱讀完成的測算快照；調整草稿參數後，必須重新執行才會更新數值。

## 操作

1. 按「完整設備案例 · 3 天」載入 513 kWh、SOC20–100% 的物理投影。保留原車次與直充需求，換電按每次410.4 kWh計算，連續重複來源第一天共三日；不改寫來源原表。
2. 拖動時間軸，或輸入自期初起的精確分鐘。D1是第一天；前後箭頭跳至功率變化時刻，播放逐事件前進。每小時模式則按小時跳轉。
3. 全圖保留92節點、96連線，包括進線、計量、開關、箱變、SST、PCS、雙母線、跨站連線、16組DD及電池倉、2個重卡換電工位、2堆／4終端／8槍、2個CATL乘用車站及補償櫃。實際數量由結果拓撲決定，不固定繪製示意設備。
4. 全圖看結構，放大看數字；A/B區供電按鈕定位上游，拖空白處可平移。搜尋名稱或ID能定位每一個元件。點節點後，其相鄰連線加亮；側欄可點相鄰元件繼續追查。
5. 切換「當下功率 kW」與「每小時電量 kWh」。每張卡顯示輸入、輸出、損耗及狀態；側欄另列末端吸收、容量、需求、各連線及完整算式。
6. 展開「對照此小時電量帳本」，同時看到既有帳本值及功率區間積分。可匯出全圖JSON，包含全部節點／線、精確時刻、原精度數字、引擎版本及參數快照。

紅色為AC、藍色為DC；正功率線增粗，零值／未計算線變灰；停用或閉鎖線為虛線。線交叉不代表節點。零功率不等於不帶電。供給受限、輔助不足、停用、閉鎖及小時內狀態變化分別顯示。

## 數值契約

`packages/station-engine`在每個實際分配區間開始，完成元件／連線kW彙總後、更新kWh帳本前，附加記錄。不改变電力分配、電量、庫存或結算算術。

`RunResult.powerTrace`為新增的可選記錄；專案schema仍為1.3。節點樣本欄位為分鐘、輸入kW、輸出kW、損耗kW、末端吸收kW、末端需求kW、狀態碼。連線樣本為分鐘、kW。狀態碼0＝配置啟用，1＝配置停用，2＝輔助聯鎖，3＝輔助供給不足；一般需求未滿足由實際供給與需求判定。

每條訊號獨立按「數值完全相同」作無損連續區間壓縮，零值也明確記錄；不取平均、不插值、不四捨五入。樣本適用 `[tᵢ,tᵢ₊₁)`，最後樣本至模擬期末。期末滑桿顯示最後區間的左極限，不能虛構模擬結束後狀態。不得用減固定epsilon方式查詢期末，避免吞掉最後事件。

驗算式：

- 元件：輸入＝輸出＋損耗。
- 分流：輸出＝所有出線合計＋末端吸收。
- 接線：非電網節點的輸入＝所有入線合計。
- 全圖：外部電網輸入＝所有設備損耗＋所有末端吸收。
- 小時電量：各功率常數區間與該小時交集的 `kW × 分鐘 / 60` 總和。

全圖與節點殘差使用原精度數值；介面兩位小數僅用於顯示。驗收容差為10⁻⁶ kW／kWh。電網數值依實際來源，不能拿按用電站別歸屬的購電量代替。

來源重播沒有功率記錄，顯示未計算與「—」。舊受限結果無trace時只可查看既有小時電量，狀態顯示未記錄，不從期初配置猜測後續停機狀態。

末端吸收包含回充、直充及輔助用電。換電交付屬電池存貨移轉，不會在充電線上再扣一次；此圖未加入即時SOC或機械作業狀態。線纜目前理想零損耗；補償櫃的無功效果未建模；CATL站僅建模交流負載，沒有乘用車逐車服務及收入。

## 驗證與範圍

`tests/power-trace.test.ts`包含7項測試：480 kW持續0.125分鐘＝1 kWh、精確邊界／期末極短停機、一般供給受限、箱變故障與SST輔助閉鎖、零值與缺失記錄、三個既有多日案例逐訊號對帳、完整三日92/96元件對帳。獨立矩形積分直接讀原始區間，不呼叫介面積分器生成預期；並检查全部事件的節點守恆與容量。

完整三日案例：788個變化時刻、trace1,054,122 bytes；34,340項逐訊號／守恆比較最大差3.637978807091713×10⁻¹²。三個解析案例另有13,828項trace對帳；這些不是原47,489項解析比較的重新命名，也不是現場實測。

SSR輸出驗證全部92節點／96連線、電池倉與槍ID、時間軸可及性、未計算狀態、真實受限數值及驗算控制。正式Worker須與來源引擎完整RunResult一致（包括trace）。本次沒有執行瀏覽器互動或截圖驗收。

31日單次執行量測：8,152事件、10,938,845 bytes trace、約29秒；此為開發運算環境結果，不是裝置效能保證。介面小時帳本僅在跨小時時重算，小時模式共用結果；功率查詢不掃描小時帳本。模擬仍在Web Worker中，拉時間軸不重跑模擬。

有限測試與守恆檢查驗證實作的一致性，不構成所有輸入或真實獲利百分之百保證。現場校準與成本完整性仍依Master Prompt128章驗收。
