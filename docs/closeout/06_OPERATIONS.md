# 06｜操作標準程序（SOP）

適用 0.8.1 單母線第一期。操作基準是「先確認資料 → 套用 → 測算 → 驗算 → 匯出」；修改設定不會自動讓上次結果成為新方案結果。網頁重整或關閉前須保存。

## SOP-01｜首次開啟與選擇基準

**目的：** 建立可辨識的一期案例。**輸入：** 網站或離線HTML；或既有專案JSON。**輸出：** 目前專案基準JSON。

1. 開啟 [網站](https://highway-swap-george.george-chen-1104.chatgpt.site) 或交付HTML。檢查頁首／頁尾版本與案例名稱。
2. 新建時使用「單母線第一期案例」；已有資料先按頂端「JSON」保存，再載入預設，避免覆寫正在編輯的設計。
3. 確認採「受限營運模擬」，不要用「來源原表重播」結果回答實際供電能力。
4. 到「設備與容量」核對每側 SST1、AC/DC3、DC/DC5、3座雙槍終端；到「供電設計」看供電路徑。
5. 將案例命名、記錄連續天數、seed與來源版本，匯出一份起始JSON。

**核對點：** 首次開啟可能尚未測算，結果留空屬正常。匯入舊JSON會保留舊模型，不會自動升成一期單母線。

## SOP-02｜修改設備、效率與供電設計

**目的：** 建立指定設備方案。**輸入：** 設備規格、效率及已知接線。**輸出：** 設備JSON／參數CSV／專案JSON。

1. 先保存目前專案。若需要新增端口或共享連接，先在「完整模型設定」完成草稿，再按「套用並重建設備連接」。
2. 到「供電設計」檢查節點、線路、啟用狀態與上下游額定，再做手動位置／連線微調。重建可能取代自訂連接與位置，不要在微調後不加核對地重建。
3. 到「設備與容量」或「效率比較」修改指定 AC/DC 的整機效率；95.35 表示95.35%，不是0.9535%。
4. 檢查箱變滿載餘量／缺口與單槍限流；額定夠大不等於上游有足夠功率。
5. 匯出設備設定供批次編輯時，使用設備參數CSV調整既有節點，整套設備JSON保存完整結構。匯入後檢查是否全部成功。
6. 重新執行測算；到元件帳確認購電與損耗變化，再匯出新結果。

**核對點：** AC/DC效率不等於替代PCS效率。新增可選模型須先補齊必要值，否則測算會阻擋。

## SOP-03｜設定 A／B 換電 SOC

**目的：** 調整共用換電窗口並同步需求。**唯一入口：**「站務配置」。

1. 在 A 或 B 卡片輸入「回收 SOC 下限」「交付 SOC 上限」。有效範圍為 `0≤下限<上限≤100`。
2. 檢查每次補電與全期電量預覽。例如513 kWh、20%→80%，每次307.8 kWh。
3. 按「套用 A／B 區 SOC 並同步全期換電需求」。此動作會重算該站所有日期的換電kWh，車次與直接充電不變。
4. 修改另一站時重複上述步驟；離開頁面或改其他站務參數前先套用，未套用輸入不保存。
5. 若剛修改電池容量，再套用一次SOC以同步需求；若另有逐艙覆寫，到「完整模型設定」檢查覆寫值。
6. 保存JSON、重新測算、核對庫存與服務量。若希望年度劇本也使用此需求，另按SOP-04保存代表日。

**核對點：**「設備與容量」不再提供第二組SOC輸入。修改共用SOC不代表已校準電池充電曲線或SOH。

## SOP-04｜編輯逐時需求與三劇本

**目的：** 定義到站需求並決定年度代表日。**輸出：** 需求CSV／JSON與完整專案JSON。

1. 到「逐時案例」，選高／中／低並載入劇本。載入需求不重置設備與效率，但會替換相應需求資料，先保存既有修改。
2. 選日期與A／B站，修改換電／充電車次、總kWh、電價／服務費與AC子集。AC子集必須小於等於總量；DC自動以差額計算。
3. 檢查來源原始總價與「精確電價＋服務費」模式，選定本次計價方式。不要用修改來源來消除不一致。
4. 要用Excel編輯，匯出需求CSV，保留欄名與鍵值，另存UTF-8後匯入。部分修改用合併；全期取代須完整覆蓋。
5. 確認均勻或固定seed到站方式。自行新增逐車事件時，核對是否與逐時生成需求相加，避免重複計車。
6. 若此日要成為十年規劃代表日，明確按「將第 N 天 A＋B 更新至…劇本」類操作，確認選定的負載與日數；單純改表格不會更新已保存劇本。
7. 保存需求檔與專案JSON，重新測算。

**核對點：** 來源410 kWh與513×80%=410.4 kWh不同。保留來源需求，或明確按SOC重算，兩種操作應在報告記錄。

## SOP-05｜執行測算與判讀結果

1. 檢查模式、天數、價格與資料缺值。只要啟用物理模組缺必要值，先補齊或明確停用；不得填0假裝有資料。
2. 按「執行測算」，等待完成訊息。失敗時保存診斷；畫面可能仍有上次成功結果，不代表本次成功。
3. 到「模擬結果」檢查需求、交付、未交付、完成次數、排隊與購電。
4. 檢查期初與期末庫存。期末較低代表使用初始電量，不能直接把原始一天交付量乘365當持續能力。
5. 查來源電表與元件帳，確認負載、損耗與費用可追溯；檢查是否有站用不足、電池不相容或功率瓶頸診斷。
6. 需要比較另一個方案前，將成功結果加入情境比較並保存JSON；比較時確認不同項以外的需求與價格一致。

**輸出：** 一次成功結果及其參數快照。不要以目前編輯頁的值替代快照中的實際輸入。

## SOP-06｜能量流與SOC驗算

1. 測算成功後打開「能量流驗算」。
2. 選「當下功率」並拉動時間軸，點選SST、箱變、充電機、槍或電池倉，看kW、限制與SOC。
3. 選每小時／區間累計，指定起訖時間；核對此模式的單位是kWh，電池SOC是終點狀態。
4. 先核對單元件輸入−輸出−損耗，再看全站外部與營運帳，勿將每層輸出再加成總供應。
5. 用相鄰窗口比較整段，特別留意恰在期末完成的服務與離散損失。
6. 匯出驗算數值並記錄窗口、模式與結果快照；截圖僅作說明，數值檔作覆核依據。

## SOP-07｜十年估算與 SST／PCS 比較

1. 打開「十年估算」。確認2027低、2028–2029中、2030–2036高，設備採一期。
2. 調整每年營運日與代表日占比；占比是需求日折算，不是設備效率或所有功率縮放。
3. 按「測算三種負載與背景用電」，等待六組三日案例完成。核對各組期末庫存、估計供應與缺口。
4. 查看「使用 SST 比改用 PCS：累計省下多少電費」；年度柱與累計線使用萬元CNY，並有明細表。
5. 將「替代方案 PCS 效率」或每度電價值調整為本次假設；這兩項只改效率比較，會即時重算，不需要重跑同一物理案例。
6. 修改設備、SOC或已保存劇本後，重新執行六案例。出現過期／未測／不支援或空值時，先處理原因，不解讀為0收益。
7. 匯出本頁當前CSV與估算JSON，連同假設保存。結果XLSX仍採最後成功測算快照，可能不是剛改過的規劃假設；需最新規劃資料時優先保存本頁匯出。

**判讀：** 正值表示SST省電費，負值表示相同交付下更費電；未包含設備價差、OPEX、稅、容量費與折現。現行預設約168.77萬元CNY是模型案例結果，不是商業保證。

## SOP-08｜保存、匯入與交付

| 檔案 | 應用 | 保存內容／注意事項 |
|---|---|---|
| 頂端專案JSON | 保留目前方案與稍後重算 | 目前已套用Project，不是最後結果 |
| 需求CSV／JSON | Excel批次改需求 | 需求與價格；不取代全設備與結果 |
| 設備JSON／CSV | 整體設備或既有參數調整 | 匯入不等於同步需求，SOC變更後另明確套用 |
| 完整模型草稿JSON／CSV | 保存未套用詳細設定 | 需套用才進入Project |
| 結果XLSX | 審查與還原輸入 | 最後成功快照與帳本；以Project_JSON還原，不任意反推展示表 |
| 十年CSV／估算JSON | 保存當前年度與比較假設 | 與最後RunResult XLSX的時間點分開記錄 |

交付時建議同包保存`project.json`、`result.xlsx`、`planning.json`、`planning.csv`、驗算窗口數值與說明。檔名加案例名、日期及版本；實際檔案hash記錄於 [交付清單](08_DELIVERY_MAINTENANCE.md)。關閉頁面前，確認檔案真的下載完成且可重新匯入。

## SOP-09｜常見問題與處理

| 現象 | 常見原因 | 處理 |
|---|---|---|
| SOC改了但需求沒變 | 尚未按套用、或年度仍用舊代表日 | 按站級套用，再保存代表日及重算 |
| 測算後仍看到舊數字 | 本次失敗、結果快照未更新 | 查看成功訊息與快照名稱，不以目前欄位判斷 |
| 高負載未全部完成 | SST／分支功率、互斥、槍、庫存或工位限制 | 查診斷、時間軸與期末排隊，不能直接增加營收 |
| 省電圖留空 | 六案例未完、過期、不支援模型或缺帳 | 重新批次測算；核對比較適用條件 |
| 累計省電費為負 | 替代方案效率較佳 | 核對效率與邊界；允許真實負差额 |
| 背景日仍有電費 | 乘用車與站用負載持續運行 | 查負載排程；若評估整站收入需補對應營收 |
| JSON與XLSX不同 | 保存時間點不同 | 重新測算後另存，保留快照證據 |
| 離線空白或無法下載 | 產物／瀏覽器限制 | 記錄錯誤與版本，重新取得交付檔；依UAT處理，不關閉安全機制湊通過 |

## SOP-10｜版本還原

先保存現況，再明確選定欲恢復的來源commit、網站版本與離線版。SST／PCS改圖前的還原點见 [還原紀錄](../RESTORE_BEFORE_SST_PCS_CHART.md)，它會回到舊圖及舊比較基準。此後曾有其他修改，不能把「上一版」當成唯一可識別目標。

在副本／分支檢查，再以新的前向提交恢復來源，保留歷史。網站與離線檔各自核對版本；還原後執行相應驗證與保存。一般使用者的案例JSON還原，不等於應用程式版本回復。
