# 01｜需求規格書（REQ）

文件版次DOC-1.0；適用範圍與來源版本見 [00基準](00_PROJECT_BASELINE.md)。本次將已確認決策與現行功能整理成40項可追溯REQ，編號為本次追溯用途；不是聲稱開發前已有相同編號的簽核規格。需求基準需由專案負責人在結案時覆核。

## 1. 規格與驗收用語

- P0：本期主要計算、操作與資料正確性需求；P1：交付、可用性、追溯及可選能力管理需求。此分級供文件管理，不是已核准的合約優先級。
- 「應」為可驗收的行為；「預設」可由使用者修改；「假設」需要來源或實測確認。
- 此處列驗收条件，實際證據狀態另見 [05](05_VERIFICATION_REPORT.md) 及 [07](07_TRACEABILITY.md)。有程式／測試不等於接收者已簽認。
- 使用者決策來源：單母線第一期、95.35%整機效率、固定一期十年、SST／PCS比較及SOC入口整併；完整歷史仍留在 [MASTER_PROMPT](../MASTER_PROMPT.md)。

**驗證／操作：** TC-005,TC-006,TC-020；SOP-04,SOP-08。實現與證據見[追溯矩陣](07_TRACEABILITY.md#req-035)。

## 3. 非目標與接受邊界

本期REQ不要求十年自動擴建、實體SST並聯控制驗證、短路保護設計、完整AC潮流、最優EMS證明、多使用者雲端資料庫或對真實獲利的保證。完整模型中的可選元件不等於一期已啟用；原生瀏覽器和現場驗收狀態需另外列管。

## 4. 變更與核准

需求有變更時保留REQ編號，記錄原文、修訂、原因、來源、受影響程式與TC。若新增範圍，另新增編號；不得只改測試預期讓新程式過關。需求覆核人、核准日期與排除條件填於 [結案簽核表](09_CLOSEOUT_REPORT.md)。
