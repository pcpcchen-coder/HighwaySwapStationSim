# 04｜測試計畫與可重現程序

## 1. 目的與狀態定義

測試用于證明指定版本在指定輸入下符合 REQ。下列是可再次執行的測試程序，不代表 2026-10-02 已重跑。已知結果見 [驗證報告](05_VERIFICATION_REPORT.md)，本次只執行文件檢查。

| 狀態 | 定義 |
|---|---|
| 通過 | 此次指定來源、輸入與程序執行後符合預期 |
| 歷史通過 | 既有日期／版本記錄通過，本次未重新執行 |
| 有測試、待執行 | 找得到測試實現，尚無本次執行紀錄 |
| 待驗收 | 需原生瀏覽器、實體設備或接收人確認 |
| 不適用／範圍外 | 明確不在本期驗收範圍，需記錄理由 |

## 2. 測試層與責任

| 層 | 測試內容 | 預期執行角色 |
|---|---|---|
| 單元／回歸 | schema、公式、容量、服務、財務邊界 | 開發人員 |
| 獨立解析 | Python Decimal 預期與引擎比較 | 數值驗證人員 |
| 整合 | 正式 Worker、SSR、DOM、JSON／CSV／XLSX | 測試人員 |
| UAT | 實際瀏覽器操作、交付檔、還原演練 | 接收人員 |
| 現場校準 | 電表、SOC、排隊、設備損耗及量測誤差 | 電氣／營運／設備方 |

本期既有自動化測試不涵蓋最後兩層全部內容。不得把 `test:offline` 的 JSDOM 通過寫成 Edge／Chrome 的 `file://` 與 CSP 實機通過。

## 3. 前置條件與執行順序

在 Linux 或相容的工程環境，使用 Node.js 24+、Python 3 與 lockfile 所指定依賴。現有建置脚本使用 Bash 及 GNU 工具；Windows 建議在 WSL 執行，macOS 要先確認工具相容性，不承諾原生 shell 直接可用。

```bash
git rev-parse HEAD
node --version
python3 --version
npm ci
npm run typecheck
npm test
npm run verify:load-planning
npm run verify:single-bus
npm run build:offline
OFFLINE_HTML_PATH="$PWD/outputs/HighwaySwapSim-0.8.1-offline.html" npm run test:offline
```

`npm test` 已包含核心、三組既有獨立驗證、正式建置與 `tests/*.test.mjs`，其中含離線測試；最後針對明確交付檔再驗一次，是為核對實際產物。`verify:load-planning`、`verify:single-bus` 是額外規劃腳本，並不由現行 CI 的 `npm test` 自動涵蓋。現有 CI 執行 `npm ci → typecheck → npm test`，見 [workflow](../../.github/workflows/ci.yml)。

先取得每項命令退出碼與完整 log，再彙總。任一失敗先保存輸入、錯誤及原預期，不能修改 fixture 湊成通過。來源未變且已有足夠針對性證據時，不為增加測試數字而重複運行。

## 4. 測試案例規格

每項 TC 執行記錄均須保存來源 commit、Project JSON、必要 log 與結果。以下預期條件是驗收斷言；自動化檔案連結詳見追溯矩陣。

| TC | 前置／輸入 | 執行步驟 | 可核對預期 |
|---|---|---|---|
| TC-001 初始設備 | 新建一期專案 | 統計啟用節點、端點與分支 | 每側 SST1、AC/DC3、DC/DC5、8倉、3雙槍終端6槍；無舊獨立超充 |
| TC-002 供電與支援 | 一期拓撲，雙側不同需求 | 分別要求 A 支援 B 及 B 支援 A；提高總請求 | 路徑可達；總 SST≤3360 kW；不重複使用來源；B電網不直接供SST |
| TC-003 效率邊界 | 固定輸出、95.35% AC/DC | 降低一台效率，重算與往返匯出 | 該路徑購電增加、輸出仍受額定；不重複計轉換級；覆寫可還原 |
| TC-004 共享／優先 | 同側外槍與電池同時需求 | 供 AC 外槍，觀察 AC／DC 回充；降低站用供電 | AC 組互斥，DC 組可独立回充；必要站用不足有相依停機 |
| TC-005 三劇本 | 未改來源三劇本 | 核對逐時加總與AC子集 | 高80620、中66270、低52330 kWh／日；DC=總量−AC，無負值 |
| TC-006 需求編輯／到站 | 多日、固定seed，合併及取代檔 | 修改一列、重排檔案順序；匯入錯誤列 | 合法變更可重現；非法批次原子拒絕，不破壞他列與設備 |
| TC-007 SOC 範圍 | A20–80%、B30–80%；513kWh | 套用 A 再 B；測0、100、小數、反向、空白 | A307.8、B256.5 kWh／次；全期同步；他站與拓撲保持；非法區間拒絕 |
| TC-008 電池物理 | 固定kWh、SOH不足、分段功率、非線性曲線 | 逐事件執行，檢查配對及SOC反解 | 不縮減原需求；不可行保留未交付；分段與曲線能量一致 |
| TC-009 連續營運 | 固定多日輸入 | 追蹤開始、完成、期初期末庫存與排隊 | 交易與庫存可核對，需求=交付+未交付；期末缺口不消失 |
| TC-010 缺值與校驗 | 啟用模組但必要值null；未知／重複ID | 保存草稿、尝試套用與測算 | 草稿可保留未知值；不可執行條件給出診斷；不以0冒充已知 |
| TC-011 守恆 | 固定解析案例與單母線案例 | 比較元件、連線、來源與營運帳 | 依各測試原容差通過；常見能量1e-6 kWh；金額依結算政策 |
| TC-012 時間區間 | 0長度、相鄰、子分鐘、期末窗口 | 拖動／程式選定區間，積分並比較整段 | 相鄰可相加、0長度為0、離散事件不重複；SOC為終點狀態 |
| TC-013 方案與結果快照 | 已有成功結果後改設定 | 改SOC、效率、劇本，檢查舊結果與新專案 | 舊結果參數不被改寫；年度過期結果不當新方案；成功重算才更新 |
| TC-014 年度背景與庫存 | 三負載＋三背景，各3日 | 檢查庫存扣除、背景天數與年度係數 | 不把期初存量變年售電；無重卡日仍計背景電費；第一期固定 |
| TC-015 同量效率收益 | 相同D、ηPCS98%、0.67元 | 核對來源加權；改等效率、較高PCS效率、零電價 | 正／零／負值合理；AC/DC效率不冒充PCS參數；不支持條件null |
| TC-016 計費與財務 | 原始總價模式、精確模式、成本缺值 | 核對逐來源結算、收入、成本與規劃表 | 不以一次總量取分替代逐時政策；缺完整成本不產出無依據投資結論 |
| TC-017 匯入匯出 | 目前Project與最後RunResult不同 | JSON／CSV／XLSX往返、錯檔、Unicode、null | 按各格式邊界還原；展示表不冒充資料真相；非法匯入不部分套用 |
| TC-018 正式介面與離線 | 正式建置、實際單檔HTML | SSR／DOM掛載、切劇本、Worker測算、改效率、下載 | 無React啟動空白；SOC僅站務頁；內嵌Worker和匯出有效 |
| TC-019 選配模型 | 固定完整模型案例 | 啟用PV／ESS／備援／線損及其參數 | 模組帳本與邊界符合指定案例；不得據此宣稱一期已啟用 |
| TC-020 交付／還原／文件 | 已選版本、檔案與追溯矩陣 | 核對manifest、SHA、REQ連結；在副本做還原 | 版本清楚、可找回輸入及證據；此輪只做文件部分，還原演練待辦 |

## 6. 容差與失敗處理

沿用每個測試實際容差，不為讓結果通過而放寬。能量精度、金額四捨五入、圖面顯示小數是不同概念；圖上差0.01不必然等於核心錯誤，亦不能用圖面四捨五入掩蓋核心差異。

失敗記錄至少包含：TC／REQ、實際commit、輸入、預期、實際、差值、錯誤碼、重現步驟、原因分類、修正commit及重測結果。應區分產品缺陷、測試匯入／定位錯誤、來源資料不一致與測量誤差。

## 7. 放行與簽核

候選版本只有在必需測試通過、阻斷缺陷關閉、案例可還原且限制已揭露時，才提交接收者驗收。現場效率、保護與服務量承諾須另有實測與設備方簽核。此文件不代替驗收人的確認。
