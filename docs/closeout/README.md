# HighwaySwapSim 結案文件總目錄

文件版次：DOC-1.0｜整理日期：2026-10-02｜產品基準：0.8.1／schema 1.3。此套文件供結案報告撰寫、工程覆核與後續維護使用，**不是已簽核的結案證明**。

本專案建立高速公路雙服務區的供電、充換電需求、電池庫存與營運估算工具。文件依「為何要做 → 要做什麼 → 如何設計 → 如何實現 → 如何證明 → 如何操作 → 如何交付」分開撰寫，避免以操作畫面代替需求，或以測試通過代替現場驗收。

## 2. 各階段完成條件

| 階段 | 輸入 | 應產出 | 進入下一階段前確認 |
|---|---|---|---|
| 需求確認 | 使用者決策、來源資料、限制 | REQ 編號、需求文字、驗收條件 | 額定口徑、共享方式、範圍有定義 |
| 設計 | 已確認 REQ | 拓撲、資料契約、公式及假設 | kVA／kW／kWh、母線及營運邊界一致 |
| 實現 | 設計與資料 | 程式、可操作功能、匯出格式 | 沒有用虛構參數補齊未知資訊 |
| 測試 | 固定版本與固定輸入 | TC 執行紀錄、差異、證據 | 通過／失敗／未測分開；保存原始結果 |
| 操作交接 | 可用版本與 SOP | 案例 JSON、結果 XLSX、操作確認 | 接收者可自行保存、重算、驗算 |
| 結案 | 上述文件與未結事項 | 結案正文、附件、簽核表 | 範圍、版本、未測項、責任人明確 |

## 3. 使用規則

1. 現行配置以本套文件及 [SINGLE_BUS_PHASE1](../SINGLE_BUS_PHASE1.md)、[SST_PCS_COMPARISON](../SST_PCS_COMPARISON.md)、[SOC_SETTINGS](../SOC_SETTINGS.md) 為準。歷史 `MASTER_PROMPT` 保留需求來源，不表示所有構想皆已交付。
2. 本次只整理與補寫文件；未重跑物理測算、未重新做瀏覽器／場站驗收。歷史結果都附版本或日期，文件檢查另列於 [文件檢查紀錄](DOCUMENTATION_AUDIT.json)。
3. REQ 的「已實現」是程式狀態；TC 的「歷史通過」是指定測試狀態；「驗收完成」須由接收者簽認。三者不可互換。
4. 文中【待填】只用於未知行政資料、簽核、實測與報價；現有技術內容已填寫，不以空白章節代替交付。
5. 更新功能時，同步修改 REQ、實現、TC、SOP 及追溯矩陣，再追加驗證與交接紀錄。需求刪除或替代須保留決策原因。

## 4. 原有文件的定位

- [MASTER_PROMPT](../MASTER_PROMPT.md)：原始與追加需求全文，保留歷史。
- [HANDOFF](../HANDOFF.md)：按版本記錄接手狀態；[VERIFICATION](../VERIFICATION.md)：按日期保留執行紀錄。
- [COMPLETE_MODEL_GUIDE](../COMPLETE_MODEL_GUIDE.md)：完整模型可選模組的詳細參數，不代表一期預設皆啟用。
- [舊版 README 存檔](../history/README_before_closeout_2026-10-02.md)：本次整理前的入口內容，僅作沿革查閱。

原有報告、PPT、PDF及數值證據均保留。引用 0.3／0.6／0.7 的成果時，必须寫明其版本與案例，不能將歷史簡報標示為 0.8.1 全功能驗收。
